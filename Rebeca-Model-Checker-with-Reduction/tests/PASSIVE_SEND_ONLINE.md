# Online action selection with sends to passive destinations

This extends the isolated-local online rule without reading a full graph. It is
not a rule for feedback routing, general conditionals, time or arbitrary sends.
LoadBalancer remains outside its scope and retains 38 states/46 transitions.

## Static certificate

A supported source handler is nullary, has no inheritance, and consists only of
constant primitive local assignments plus at most ONE direct known-rebec send.
The send is unconditional, nullary and untimed; explicit after/deadline suffixes,
self/sender/computed receivers, unknown suffix classes, unresolved destinations,
arguments, extra sends, guards, arithmetic, calls and assertions all reject it.
Time built-in names are excluded from local scalar footprints.

The target handler must have an empty effect: its entire body is an empty block
or nested empty blocks, with no parameters, inheritance, reads, writes, sends or
calls. Destination identity is resolved per INSTANCE through known-rebec bindings,
not just class name. Two source actions are independent only if their local
write sets are disjoint and, when both send, their destination instances differ.
The original JSON same-instance dependency table is not rewritten.

## Runtime sufficient conditions

The ordinary ARIA/no-property-file/no-symmetry gate still applies. The runtime
selector additionally requires:

- All pending messages of the chosen source actor have certificates.
- Every queued message of every other actor is passive; no active continuation
  or feedback handler can execute before the chosen action.
- All pending messages are equally ready now with infinite deadlines; all actor
  priorities agree, and pending/future target message priorities match. Parameters
  have zero frame size. Unknown IDs or delayed work reject the certificate.
- Each send target is passive, is not the source, and has compatible time/priority.
- Current target queue lengths plus ALL sends potentially generated by the source
  queue fit, with an empty terminator slot reserved. This bounds every enqueue
  even if no destination is scheduled to free space first.
- The chosen message occurrence is unique. Its target queue is currently empty,
  and no other source alternative sends to that target. Its local writes commute
  with all other source alternatives.

If no candidate satisfies every condition, ordinary actor-level POR/full fallback
runs. The existing closed-successor BFS proviso is still applied to the selected
action trial; failure returns to full alternatives. The solver does not catch or
ignore deadlock, assertion, deadline or overflow errors.

## Persistence argument within this fragment

Before the chosen action executes, only the other certified source handlers and
already enabled passive handlers can run. Other source handlers cannot write its
variables or touch its destination queue. Passive handlers have no effect outside
consuming their own queued message; they neither create future work nor modify
source variables. The chosen action's destination starts empty and cannot be
filled by those other handlers, so it has no conflicting preexisting consumer.
All sends are bounded independently of scheduling, so queue capacity cannot
create an order-dependent overflow. Equal times/priorities and absent timing
operations avoid changing eligibility via time or scheduling priorities. The
chosen source message stays enabled. All its effects commute with paths avoiding
it, and no custom property observes a discarded intermediate state. The ordinary
cycle proviso remains in place.

These are sufficient conditions for this narrow terminating fragment, not a
claim of soundness for every actor model. Destinations that mutate state, send
onward or feed back require additional reasoning and are deliberately excluded.

## Validation

The actual Java certificate code is compiled against typed AST fixtures to test
known-instance resolution, shared targets/writes, active destinations, self sends,
explicit time, arguments, unknown calls and multiple sends. This does not replace
building against the external compiler JAR on the desktop.

The actual C++ selector is compiled under C++11 at O0/O2. Tests include disjoint
passive targets, conflicting/active/occupied targets, aggregate queue bounds,
unknown messages, sender parameters, clock/deadline/priority differences and the
property gate. Previous local/alternative/FTTS/reference tests still pass.

Controlled generated-C++ replay with explicit metadata (includes Bootstrapper):

| Scenario | Previous states/transitions | New states/transitions | Outcome |
| --- | --- | --- | --- |
| Disjoint passive sends | 9 / 9 | 6 / 6 | deadlock, stopped |
| Shared destination queue | 8 / 9 | 8 / 9 | deadlock, stopped |
| Original LoadBalancer | 38 / 46 | 38 / 46 | satisfied |

Deadlock counts are discovered states up to the first error, NOT full-space sizes.
The new standalone Rebeca fixtures differ from the mutated-C++ replay above;
their counts must be measured after native regeneration, not assumed from this table.

## Desktop regression

```bash
bash tests/compare_passive_send.sh
bash tests/compare_isolated_local.sh
bash tests/compare_loadbalancer.sh
```

The new script checks a positive model and an aliased shared-queue model. Both
must stop with a deadlock trace; only the positive one may log
POR_PASSIVE_SEND_ACTION. The default solver still stops at the first model error.
Runtime COND evaluation and online support for LoadBalancer's feedback cycle are
not implemented by this change.
