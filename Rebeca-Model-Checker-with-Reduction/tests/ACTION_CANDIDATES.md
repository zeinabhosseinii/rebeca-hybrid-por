# Explicit online action candidates and representative reasons

COND work is paused. This change makes the existing online selection rules
explicit and completes enumeration within their supported certificates. It does
not claim a universal independence procedure for arbitrary actor programs.

## Selection object and enumeration

`PorCandidate` identifies actor, message-server ID, proof category and the exact
queue-alternative indices that must be executed. Message ID zero explicitly means
an unsplit actor union; it is never presented as one independent action.

For each eligible actor, in the existing configured preference order:

1. Enumerate every action admitted by the isolated-local certificate.
2. If none exist, enumerate every action admitted by the passive-send certificate.
3. Otherwise apply the existing global dependency check to all queue alternatives.
   If they share one handler ID, represent that action with **all** queue indices.
   Different parameter frames are nondeterministic outcomes, not duplicate actions
   that can simply be dropped. If handler IDs differ, retain one explicit actor
   union; global cross-actor safety alone does not prove same-actor independence.
4. Execute all outcomes of each candidate. The existing exact adjacent-entry
   equivalence check remains the only duplicate filter. Every nondeterministic
   branch is retained. Deadline/deadlock/assertion exceptions still stop normally.
5. Apply the unchanged closed-successor BFS proviso to every outcome. A rejected
   action now permits trying the next certified action of that **same actor**
   before proceeding to the next actor. Previously only the first special-case
   action was attempted. If no candidate passes, expand fully as before.

Preparing later candidates does not execute their handlers. Every trial restores
the source configuration before the next alternative; actual proviso checks are
performed at trial time. States/edges generated by a rejected trial retain the
pre-existing solver behavior; they are not deleted or bypassed.

No static priorities were imposed on the unannotated dynamic model. No dependency
matrix or COND classification was weakened. The global check still includes
future methods, except the previously certified permanently disabled blockers.

## Trace and explanations

`POR_REPRESENTATIVE` records scope, actor, handler ID, alternative count and one
of `isolated_local`, `passive_send`, `global_dependency_check`, or
`unsplit_actor_union`. `POR_TRIAL` repeats that identity with its acceptance.
`POR_ALTERNATIVE` records the actual executed message/queue alternative.

`audit_action_candidates.py` links these events to dependency blocks, quiescence
exclusions and closed successors. It rejects changed identities, execution of a
different message, missing trials and inconsistent acceptance after proviso
rejection. Completed satisfied runs require a decision per reached state. Failed
runs allow the last trial to terminate with a real first-error trace; they are
not misreported as completed spaces.

## Measured checks

Fresh Java generation and C++11/O2 execution reproduced:

| Run | States / report transitions | Result |
|---|---:|---|
| Unannotated baseline | 101 / 202 | satisfied |
| Static priorities | 22 / 26 | satisfied |
| Dynamic AST | 27 / 32 | satisfied |
| Dynamic JSON | 27 / 32 | satisfied |

Each dynamic trace accepts 25 explicit action identities, all under the existing
global dependency check. Two states expand fully. The finite full-graph auditor
again verifies all 25 actual selections, both full expansions, all 30 distinct
exported edges and four closed-successor rejection witnesses. This is finite
LoadBalancer evidence, not a proof of arbitrary-model POR.

The two pure-local fixtures and two passive-send fixtures still stop at their
first deadlock. Conflicting local handlers and shared-queue sends explicitly
retain actor-union fallback. A new parameter fixture queues Set(1) and Set(2):
both alternatives execute under the same action identity, and both baseline and
ARIA stop on deadlock. Its counts are first-error prefixes, not complete spaces.

The actual trial-loop unit harness forces the first certified action to reach a
closed successor and verifies that the next certified action is executed and
accepted. The collector harness protects all alternatives, later candidates and
unsupported-splitting fallback. The underlying local/passive selector tests also
verify that starting enumeration later cannot hide an invalid earlier message.

Replayed policy controls remain: dynamic actor-priority preference 42/50;
dynamic Hub-message priorities 27/32; static actor-only priorities 37/47;
static message-only priorities 101/199. Hence there is no evidence for claiming
the 27/22 gap has disappeared. See HUB_ALTERNATIVES.md for the policy distinction.

## Reproduce

```bash
bash tests/compare_action_candidates.sh
```

This builds/generates four main modes, runs the actual collector/trial tests,
regenerates the complete normalized reference, checks actual AST/JSON selections,
and runs first-deadlock and distinct-parameter regressions. The decision report
is `tmp/action_candidate_decisions.json`; semantic reports are
`tmp/action_semantics_{aria_ast,aria_json}.json`.

This step completes explicit candidate handling for the present certificates.
Same-actor feedback cases not covered by those certificates still need a stronger
independence argument; their fallback remains visible rather than relabelled as
a general action-level reduction. Equal or smaller state counts alone are not
the acceptance criterion, and the source's balance comment is not a checked
formal balance property.
